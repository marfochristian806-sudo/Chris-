Drop blocks into the six columns. Each column is a stack: blocks are pushed on top and matching blocks are popped off the top.

  • 3+ identical blocks stacked on top of each other pop.
  • Every pop can trigger a cascade — combo multiplies the score.
  • If a stack gets too tall… stack overflow. Game over.

    How this game uses the Stack data structure

    1 · One stack per column

    Each of the six columns is a Stack object implementing push(), pop(), peek(), size() and isEmpty(). Blocks are only ever added or removed from the top — never the middle — which is exactly the LIFO rule.

    2 · Clearing = repeated pop()

    A clear reads the top block with peek(), counts how many identical blocks sit consecutively on top of it, then pops them one by one. Because pops always come off the top, no block ever has to "fall through" another block — the structure stays valid by construction.

    3 · Undo = a second stack

    Every move pushes a full state snapshot onto a history stack. undo() pops that snapshot and restores it — the same double-stack technique used by undo/redo in editors.

    4 · Game over = stack overflow

    The loss condition is a stack exceeding its capacity: if size() + piece.length exceeds ROWS the push is rejected and the game ends. The dashed red line on the board marks the capacity limit.
